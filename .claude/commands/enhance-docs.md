You are enhancing documentation using the **Ogawa Coffee-Inspired Documentation Framework**.

Follow these steps systematically:

## Step 1: Analysis

Read the target documentation file and assess its current state:

1. **Calculate Documentation Health Score** using Four Facets:
   - Data (commands, specs) - /25
   - Structure (hierarchy, steps) - /25
   - Meaning (definitions, examples) - /25
   - Context (why, when, who) - /25
   - **Total:** /100

2. **Identify user personas** and their journeys

3. **List gaps** across three levels:
   - Knowledge (missing facts/syntax)
   - Skills (missing examples/troubleshooting)
   - Wisdom (missing decision guidance)

## Step 2: Enhancement Plan

Create a priority-ordered plan:

**Priority 1: Critical Additions**
- [ ] Add metadata header (time, difficulty, outcomes)
- [ ] Add "Why this matters" context
- [ ] Add common issues sections
- [ ] Fill critical data gaps

**Priority 2: Structure**
- [ ] Add verification checklists
- [ ] Create decision matrices
- [ ] Add visual diagrams
- [ ] Improve navigation

**Priority 3: Meaning**
- [ ] Define technical terms
- [ ] Add practical examples
- [ ] Clarify ambiguities

**Priority 4: Context**
- [ ] Add "Why this works" explanations
- [ ] Create role-based paths
- [ ] Add "When to use" guidance

**Priority 5: Wisdom**
- [ ] Create anticipatory FAQ (8+ entries)
- [ ] Add decision support tools
- [ ] Include performance guides

## Step 3: Execute Enhancements

Apply the templates from `.claude/claude.md`:

1. **Add metadata header:**
   ```markdown
   # [Title]
   **Time to complete:** X-Y minutes
   **Difficulty:** Beginner|Intermediate|Advanced
   **Last updated:** YYYY-MM-DD

   ## What You'll Accomplish
   - ✅ Knowledge outcome
   - ✅ Skills outcome
   - ✅ Wisdom outcome
   ```

2. **Enhance each section** with Four Facets:
   - What it does (Data)
   - How to do it (Structure)
   - What things mean (Meaning)
   - Why/when/who (Context)

3. **Add decision matrices** for choices

4. **Create anticipatory FAQ** using Ogawa Coffee methodology

5. **Add role-based learning paths**

6. **Include visual diagrams** for complex flows

## Step 4: Validation

Run through the checklist:

- [ ] Four Facets all >80% complete
- [ ] Knowledge → Skills → Wisdom progression clear
- [ ] Anticipatory FAQ with 8+ entries
- [ ] Decision support tools included
- [ ] No dead ends (all sections have next steps)
- [ ] Common issues addressed (5+ scenarios)
- [ ] **New Health Score:** /100 (target >90)

## Step 5: Summary

Provide a transformation summary:

```markdown
## Documentation Enhancement Complete

**Before:**
- Length: X lines
- Health Score: Y/100
- Completeness: Z%

**After:**
- Length: X lines (+N)
- Health Score: Y/100 (+N)
- Completeness: Z% (+N%)

**Major Enhancements:**
- [List key improvements]

**Predicted Impact:**
- Time to first success: reduced by X%
- Support ticket reduction: -Y%
- User satisfaction: +Z points
```

## Remember

Apply the "Complete Gift" philosophy:
1. **Anticipatory** - Answer unasked questions
2. **Multi-Modal** - Text + diagrams + examples + tables
3. **Safe** - Context without patronizing
4. **Complete** - Nothing missing

**Goal:** Users can succeed without external help, understanding not just "how" but "why" and "when."
